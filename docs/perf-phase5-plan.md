## Can 50 cells/min be reached (the honest arithmetic, contended numbers only, overlap counted)

**Plain answer: NO at central estimates. Committed target: 42-43 cells/min steady-state (~35-36 on the 81-cell wall, ~134-137s) - lowered from the draft's "42+, expecting 44-46 steady / 38-39 wall" because the roll-up must follow the lever table's own P column (critic 1) and A now books the marks floor pending reconciliation (critic 2). 50 is a stretch outcome with ~15-20% probability (down from ~25%: the 441-vs-marks reconciliation adds a required leg to the conjunction), and only on the steady-state metric. Neither prior document said this; both judges and the critic did, and this plan adopts it.**

There are two denominators, and the target arithmetic is only honest against one of them:

- **81-cell wall metric (the committed definition of done):** 138.4-144.8s = 34.2-35.1 cells/min. Decomposition: 81 x 33.7 = 2730 cpu-s over ~141.6s x 24 cores = **80.3% machine utilization** (matches the measured 76-79% CPU). The wall responds to per-cell CPU cuts linearly only at fixed utilization.
- **N=16 steady-state metric:** 40.7 cells/min = 22.9 cpu-s/s consumed = **~95% utilization**. This is the denominator on which "33.7 -> 27 cpu-s gives 50 cpm" is true (40.7 x 33.7/27 = 50.8).

Consequence the prior documents never stated: **at 27 cpu-s/cell the 81-cell wall lands ~112-119s, not 97s.** Hitting 97s literally requires 27 cpu-s AND utilization rising 80% -> 94% (or ~23 cpu-s at today's 80%, below the stack's best-case floor). The utilization gap is ramp/drain/prefetch run-shape, which per-cell CPU levers do not touch; that is the adaptive-scheduler (Governor v2) lane on perf/adaptive-scheduler, out of phase-5 scope but required for the literal 97s number. Phase 5's job is the cpu-s/cell cut; both metrics get reported on every bench.

## Determinism gates (the specific tests, including the adjacent-cell canonical-hash A/B for the halo guard)

**G0, every gate run:** cargo build --release explicitly first. golden_hash.sh NEVER rebuilds (documented gotcha, bitten before). Never byte-compare .b_linear anywhere (container not reproducible); block-level hashes only.

**G1, every landed change:** golden hashes 5/5 + ARNIS_BLOCK_HASH parity on one ring-3 cs4 cell, change on vs off.

**G2, OSM sidecar:**
- Verify-at-bake is the primary gate: baker re-decodes its own freshly written .osmbin and compares the full element sequence against the Vec<OsmElement> just decoded from the source JSON - **bit-wise on f64 (to_bits), never PartialEq: NaN != NaN false-fails and -0.0 == 0.0 false-passes (critic 5)** - then stamps the verified bit; a sidecar that never passed this cannot exist.
- One-time fleet parity: ARNIS_BLOCK_HASH with-vs-without sidecars over every cached tile before ship.
- Staleness drill: overwrite a .json with different bytes, assert the stale .osmbin is bypassed and re-baked (content hash, never mtime; TTL re-downloads, _fresh_on_disk re-fetches, and .pbf bakes all legitimately rewrite the same filename with different bytes/order).
- Trailing-bytes drill: append junk to a .json, assert bake and fallback both read it with identical element counts (no-end() parity, annex flaw 1).
- Codec rule in review checklist: any OsmElement serde-shape change bumps OSM_SIDECAR_CODEC_VERSION, **and so does any bincode crate or config bump (critic 5): bincode is not self-describing, wire bytes change with zero shape change, and an old sidecar under a new bincode either fails open (fine) or misdecodes silently, fleet-wide and invisible to verify-at-bake, which only ever ran under the old binary. bincode joins the output-affecting pin list (G5).** Scope honesty: "byte-identical by construction" covers ordering and staleness only; the codec-bug case is covered by verify-at-bake, which is testing, not construction.
- Bake-contention drill (critic 6b): the A6 N=16 sidecar-cold (JSON-warm) arm asserts sidecars persist and verify after concurrent first-writer-wins renames (Windows rename-over-open-destination fails).
- Lifecycle: Meld's TTL/prune/re-download deletes the paired .osmbin (A7); no orphan accumulation.
- Rollback: delete .osmbin files = complete rollback, always.

**G3, diet:** B1 transposition/stride errors are caught instantly by G1 (virtually every block's Y reads the grid). B2 parity run on a cell chosen for heavy tile-boundary overlap (band ordering, 9-contributor regions), not an easy cell. B3: per-site order-sensitivity audit before reuse, skip-not-fix on failure, golden + block-hash after EACH site batch. No hasher swaps anywhere, ever.

**G4, halo guard:**
- Default-off byte-identity by construction (rect None or flag off = one dead branch); golden 5/5 as ritual (golden runs have no --canonical-regions).
- All comparisons in ARNIS_BLOCK_HASH_CANONICAL / region_content_hash currency (D2); the whole-world hash differs by construction and must never be used.
- Single-cell A/B: all 16 canonical region hashes equal, guard off vs on, per corpus cell.
- **Adjacent-cell canonical-hash A/B (the seam proof):** render both cells of a shared edge, both arms, four runs total; each cell's canonical-restricted hash must be identical across arms. This proves each cell still generates its neighbor-facing overhang identically, i.e. seam continuity is preserved, because halo ELEMENT processing is untouched and only halo STORAGE is dropped.
- Corpus per D4 (five real geographies + the adversarial boundary-straddling synthetic); bisection order seal_floating_fluid -> sweep_floating_veg -> carves -> 3D models on any mismatch.
- Automated regression test beside region_keep_tests: small bbox + keep-rect, flag on/off, assert equal per-region content hashes and dropped regions absent from the world map.
- Meld-side: permanent per-cell canonical-hash gate (D7) active whenever the flag is enabled in production.
- D1b precondition check: block-entity NBT confirmed inside the hash currency + no-fire corpus run before its landing (critic 3).

**G5, save-path and codec pins:** block-hash parity per G1; **zstd, miniz_oxide, and bincode** versions treated as output-affecting pins in Cargo.lock, any bump re-runs G1 + golden (a bincode bump additionally forces the OSM_SIDECAR_CODEC_VERSION bump per G2).

## Benchmark protocol (what must move, by how much, measured how)

**Configs:** (1) single ring-3 cell, T=2, uncontended cpu-s + per-phase marks (osm_fetch, parse_osm, element_placement, tile_merge, elevation, save); (2) N=16 steady-state sweep; (3) standard 81-cell Bucharest cs4 wall, 1:1, blinear + stream-to-disk, warm caches, fixed binary per arm. Every run reports: contended cpu-s/cell (primary metric, less scheduler-noisy than wall), wall, both cpm metrics, utilization = sum(cpu-s)/(wall x 24). The 93% efficiency figure is a measurement of today's mix, not an invariant: recompute per arm, never assume (judge correction to all three designs' cells_per_min fields).

**Repeats and significance:** 2 per arm minimum for large expected effects (WS-A); **4-5 per arm for small-effect arms (halo flag, B3, C1)**, whose predicted deltas sit at the +/-2.3% spread. A delta must clear the spread to count; below 2x spread it is labeled provisional. Diet fixes are additionally measured stacked (B1+B2+B3 vs baseline) since the combined bracket clears the noise floor when individuals may not.

**Booking rules:** contention relief is booked only when the N=16 gain >= the N=1 gain (GPU caves grew -28% -> -31%; blur transpose was flat +2.5% at both and was NOT the seat). Flat gains ship as free CPU, booked against cpu-s only. Second-order bandwidth relief is booked at zero until the N-growth signature appears, and may be claimed by at most one lever.

**What must move, per stream:**
- A: ring-3 osm_fetch 946 ms -> <=450 (tokenizer-dominant) or <=650 (allocation-bound). **Reconciliation deliverable (critic 2): 441 cpu-s/run implies 5.4 cpu-s/cell vs the ~3.2-3.5 contended the marks allow - A1/A6 must attribute the 1.6x gap (halo tiles, decode outside the osm_fetch mark, or 441 wrong) before any booking above the floor; the 441 -> <=170 run-wide target stands only if the 441 figure is validated, else the target is the marks-bound residual.** Cold-run regression <1%, **with cold DEFINED as sidecar-absent/JSON-warm - network fetch excluded, since its variance dwarfs 1% and makes the gate unevaluable (critic 6a).** One N=16 sidecar-cold (JSON-warm) arm must show concurrent bakes persisting (critic 6b). 81-cell wall delta re-bracketed off the floor booking (roughly -5 to -10s central; -17s only on the reconciled high bracket).
- B: per-fix accept gate per B0; go/no-go on the stacked delta.
- C: single-cell save-phase cpu-ms down >=10% to proceed to N=16.
- D: E3 single-cell >=0.5 cpu-s or the flag is killed; N=16 at 4-5 repeats; RAM delta measured (E2), not derived.
- Cumulative stacking A -> A+B -> A+B+C -> A+B+C+D so the results table is filled left to right with measured, not modeled, numbers.
